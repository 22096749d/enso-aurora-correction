# 研究设计、数据与模型来源、验收边界

## 1. 研究问题

核心假设：给定原始预测路径、台风历史运动和季节信息，连续ENSO背景变量还能否预测原模型残差？
首轮主指标建议预先定为72小时大圆距离误差，其他时效和分组完整报告。
必须比较同一模型家族有/无ENSO，而不能仅比较“原模型 vs 更复杂的校正模型”。
低频ENSO不是直接移动台风的力量，补丁学到相关性也不意味着发现因果机制。

## 2. 三种相互独立的验收

1. 工程：能否下载、转换、运行、追踪、传回并训练？合成测试只能证明其中的接口部分。
2. 目标模型后处理：在给定Aurora版本和输入条件下，小补丁能否改善未用于补丁训练的年份？
3. 科研泛化：测试期是否也独立于基础权重所有预训练/微调/模型选择资料，是否覆盖独立ENSO事件？

v2脚本支持完成第1及探索第2；第3需要额外资料审查和足够长历史。
不因是官方开源权重就默认其对某年份“没见过”。

## 3. 权重训练期审查

本轮查到了官方论文、数据划分讨论及模型说明，但没有逐项确认当前下载revision所对应的全部预训练/模型选择日期。
因此configs/backbone_audit.json保留null，并用protocol标记回顾性探索。
审查步骤：

1. 记录models/checkpoint.json中的权重名称、revision、SHA256。
2. 查论文与补充材料中对应0.25°Pretrained的每项数据来源及年份；别用Fine-Tuned或1.5的日期替代。
3. 记录模型选择/验证期；严格独立评价不仅要避开梯度训练数据，也要避开已被用于选择模型的评价信息。
4. 若资料仍不清，向作者询问或仅保留回顾性校正结论，不编造一个截止年。
5. 把证据链接及表号/章节登记，再冻结正式训练/验证/测试划分；新建config和run。

重要区分：对一个已固定模型进行补丁训练，可以研究其历史残差，但若这些预测来自基础模型已见过的数据，
残差分布也可能过于乐观。论文必须明确这种局限，最好补充基础权重截止日期之后的验证与最终测试。
若这导致可用ENSO事件太少，可把长期弱基线/较早模型的背景效应研究与现代Aurora迁移检验分开，
不能用大量同一事件的6小时样本假装有大量独立气候事件。

## 4. 本版不是准实时业务测试

IBTrACS是事后最佳路径，ERA5是再分析，当前Niño指数可能事后修订。
两月滞后减少明显未来月平均泄漏，但不等于恢复当年可用的数据版本。
因此准确名称是“以再分析初值和最佳路径资料进行的回顾性实验”。
未来要声称业务可用，需要真实起报分析、数据发布日期档案、稳定预测系统版本与独立业务回报。
当前或未来天气环境特征若后续加入，只能用起报时已知分析或模型预测，不能用未来ERA5真值。

## 5. 有效样本与追踪覆盖

本版计划来自有过去24小时连续记录、ENSO可用、至少某个未来时效有真值的样本，每天00UTC起报。
这决定了研究人群，不能泛称全部业务台风起报。
每个时效使用不同数量真值可用样本，因此跨时效均值不能当作同一批台风的误差增长。
track失败、系统未运行、文件缺失是不同原因，分别在coverage/errors/导入覆盖表中保留。
主指标是在有预测且有标签的共同案例上比较补丁前后；必须同时汇报覆盖率，不能仅凭条件误差断言完整系统可靠。
对模型全部漏报/消亡识别本版未定义惩罚分数；后续要专门设计，不能不说明就排除。

## 6. 统计与对照

- 固定基础模型、版本、起报资料、追踪器；各补丁同样本比较。
- Ridge和树各自有无ENSO，搜索预算一致，月份特征两组均保留。
- 平均残差校正检验复杂补丁是否值得。
- 按年份为块自助抽样，保留同一年内相关性；跨年ENSO自相关仍可能存在。
- Aurora示例最终期只有3年，置信区间仅探索性，不能代替多事件独立检验。
- 正式研究增加滚动年份外推、事件块检验、ENSO块置换负对照以及环流控制。
- 模型、参数或图例选择不能根据测试结果反复优化后仍称“一次性盲测”。

## 8. 本轮已完成和未完成

已完成：本地代码复用并隔离v2目录；跨端计划/校验/汇总接口；服务器Aurora适配与Slurm模板；
9项自动测试（包括模拟文件往返及篡改检测）；合成数据全训练/测试/推理流程；Python语法检查。
服务器代码仅按官方API核对，尚未在实际GPU运行，未实际执行CDS请求、真实NetCDF转换或权重下载。
Windows命令是针对Anaconda Prompt编写，当前自动测试在Linux CPU环境完成。
没有真实补丁效果数字，不附带训练好的真实补丁。
具体软件、模型及数据在用户机器验收后，才能把对应项改为“已完成”。
