# 双端速查、硬盘预算与常见故障

这份速查不能代替完整手册。所有示例账号/地址/目录都要按管理员分配的真实信息替换。

## 一、每次重新打开终端

【本地：Anaconda Prompt】

```bat
conda activate enso-local-v2
cd /d F:\ENSO\aurora_v2
```

【服务器：SSH后，已获准使用计算节点】

```bash
conda activate aurora-server
cd /home/yourname/ENSO/aurora_v2
export CUBLAS_WORKSPACE_CONFIG=:4096:8
export OMP_NUM_THREADS=8
```

在Slurm环境中，交互计算节点断开或资源到期后需要重新申请；登录成功不等于已经分到GPU。

## 二、文件往返最小清单

| 方向 | 传什么 | 不必传什么 |
|---|---|---|
| 本地→服务器，第一次 | ENSO_Aurora_v2.zip、pilot_plan.zip | Windows Python环境、未来真值、ENSO特征 |
| 本地→服务器，扩大规模 | full_plan.zip | 已上传的相同代码和权重 |
| 服务器→本地，小试 | return_pilot.zip、一个done日志 | 全部ERA5与权重 |
| 服务器→本地，批量完成 | return_full.zip、环境/质量审计记录 | 全部多时效天气场 |

本地的samples.csv保留真值与历史特征，服务器plan只含初始定位和时间。
先用verify-plan/verify-return检查指纹，再使用文件。
如果某台机器不能联网，可在获准联网的机器用同一数据获取程序下载对应data/era5或模型缓存，再通过SFTP传输。
必须一并传每份manifest并核对指纹；模型缓存路径和checkpoint锁定信息需要正确配置。
离线安装依赖受操作系统/架构限制，不能把Windows的pip缓存直接当Linux环境用；请管理员协助提供Linux wheel环境。

## 三、硬盘和显存预算

| 位置 | 阶段 | 建议预留 |
|---|---|---:|
| Windows F盘 | 小数据、CPU训练、返回路径及多次实验 | 10—20GB起步 |
| Windows系统盘 | 若Conda环境/包缓存默认装C盘 | 另留10—20GB |
| Linux工作目录 | 单模型、少量ERA5、首次验证 | 50—100GB起步 |
| Linux工作目录 | 大规模历史预测 | 按实际起报数量估算，常需数百GB以上 |

以下是数组计算预算，不是下载实测：
标准0.25°69个动态通道，单时刻float32数组约286MB；Aurora需要两个历史时刻，约573MB。
NetCDF是否压缩、文件编码和缓存是否复用会影响实际磁盘；同一个时刻的文件只存一次。
本版直接从NetCDF构造Batch，不额外保存Pangu式两份.npy数组，减少重复磁盘占用。
--save-msl每步只保存一张地面气压图及坐标，20步未压缩图数据约83MB/起报，NPZ压缩后因场变化而异。
它不保存所有层、所有变量预测；如果后续要做环流条件补丁，需另设计保留字段和存储方案。

显存不是硬盘。普通Aurora参考约40GB显存；48/80GB是申请建议，不是固定保证。
GPU必须实际分配给作业，MIG切片和其他进程可能使可用显存少于型号标称值。

## 四、限量参数与恢复运行

| 命令 | 参数 | 含义 |
|---|---|---|
| exchange plan | --max-per-split 2 | 每个集合最多2个案例，仅小试 |
| exchange plan | --max-per-split 0 | 所有符合条件的案例 |
| server data | --limit 10 | 计划按时间排序前10个独立起报的初值 |
| server run | --limit 10 | 最多新增10个尚未完成独立起报 |
| server run | --steps 1 | 6小时单步，单独输出目录 |
| server run | --steps 20 | 120小时预测 |

数据缓存跳过前先验证指纹。成功输出目录有done.json，重跑会跳过。
只有error.json或部分文件说明上次中断；先记录错误并归档具体日期目录，再恢复。
不同steps、代码、模型revision、计划不能混在同一输出目录。
本代码没有跨日期多进程锁调度，只允许一个作业顺序处理一个输出目录；不要同时启动两个相同批次。

## 五、常见问题

| 问题 | 检查 | 处理 |
|---|---|---|
| Windows提示cd路径不存在 | 是否多解压一层，是否带F盘/d | 确认README实际位置 |
| Windows出现>>> | 在Python窗口而非终端 | exit()返回Anaconda Prompt |
| SSH超时 | 地址、端口、学校VPN、防火墙 | 向管理员核实，不猜账号 |
| SSH Permission denied | 登录方式和账号权限 | 使用授权密钥/密码，别把密码写入脚本 |
| SCP上传方向弄反 | 冒号左侧是remote host，命令的源在前 | 严格按手册两个方向示例 |
| 服务器找不到conda | 模块环境没有初始化 | 用管理员提供的module/激活方式 |
| 登录节点看不到GPU | 未申请计算节点 | 通过Slurm或管理员指定方式申请 |
| CUDA unavailable | 装了CPU torch或驱动不匹配 | 查torch.version.cuda和管理员环境 |
| pip check不通过 | 固定版本冲突 | 解决独立环境依赖，不用--no-deps硬绕 |
| Aurora包版本不符 | 与2.0.1接口适配不一致 | 用指定环境，升级须新版本实验 |
| CUBLAS deterministic报错 | 未设置CUBLAS_WORKSPACE_CONFIG | 在启动python之前按手册export |
| CUDA out of memory | 卡未分配/被占用/显存不足 | 看实际可用卡，申请更大显存，不将2×24GB当48GB |
| CDS 401/403 | 凭证、条款许可 | 在服务器配置当前账号认证 |
| CDS长时间无数据 | 队列或大请求 | 看CDS任务页，不反复申请 |
| NetCDF变成ZIP/字段变化 | 接口data_format/download_format或版本改变 | 核对官方Show API request后适配 |
| 字段缺少、expver多维、NaN | 原始ERA5结构或完整性 | 人工审查，不能无依据补零 |
| MSLP单位失败 | hPa/Pa混用或损坏 | 使用原始ERA5 Pa，不手工乘除猜测 |
| Tracker第一步失败 | 未识别到中心或资料/模型不匹配 | 查看MSLP/风场和日志，保留失败，不给未来真值重启 |
| tracker_fallback=True | 官方追踪器退回外推 | 报告比例，主试验保留并审查 |
| plan或return hash mismatch | 文件被编辑或传错版本 | 重新核对文件，别直接改manifest |
| collect没有结果 | 所有案例未完成或无有效轨迹 | 查看coverage与error，不训练空数据 |
| train样本不足 | 仍是6案例小试包或缺少年份 | 扩到预定训练/验证计划，不复制样本 |
| shrink=0 | 验证集建议不做校正 | 正常选择，不强制修改成1 |
| ENSO增益为负 | 假设不成立、过拟合或分布偏移 | 保留结果，按科研检查定位 |
