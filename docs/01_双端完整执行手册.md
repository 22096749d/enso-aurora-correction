# ENSO × Aurora 双端研究完整执行手册

版本：v2，2026-09-10。你本地是Windows + RTX 5070 Ti，服务器是Linux + 大显存GPU。
本手册包含安装、数据、模型、跨端传输、推理、训练补丁、最终测试、单例校正。
每个命令块标题都标明在哪里运行。**不要把Linux命令复制到Windows CMD，也不要把Windows路径输入服务器。**

## 0. 先明确：训练的是什么，服务器负责什么

我们不训练或微调Aurora参数。Aurora作为冻结基础模型在服务器产生预测；
本地训练的是“对原始路径误差的岭回归/梯度提升树补丁”，这部分CPU即可完成。
主问题是单个已存在台风在24/48/72/96/120小时的位置校正，训练时使用许多历史台风。

| 工作 | 运行位置 | 输入 | 输出 | 为什么放这里 |
|---|---|---|---|---|
| 项目安装、代码测试 | Windows本地 | 新项目包 | 可工作的本地环境 | 不需要大GPU |
| IBTrACS、ENSO下载清洗 | Windows本地 | 两个官方文件 | 样本、统计、数据指纹 | 数据量较小，便于检查 |
| 弱轨迹基线与补丁闭环 | Windows本地 | 清洗样本 | 基线、两种补丁、测试 | 验证研究方法和程序 |
| 起报任务计划 | Windows本地 | 样本起报信息 | plan.csv、manifest | 先明确样本与预算 |
| 传计划与代码 | 本地→服务器 | ZIP和小文件 | 服务器项目副本 | 不传conda环境、不传未来标签 |
| 权重与ERA5获取 | Linux服务器 | 官方权重、CDS | 模型、两时刻初值 | 重型文件保留在服务器 |
| Aurora推理和官方追踪 | Linux GPU服务器 | 初值、初始台风中心 | 原模型路径、告警、日志 | 约40GB级别推理显存 |
| 返回路径 | 服务器→本地 | 预测CSV及审计文件 | 本地返回包 | 不用传全部天气场 |
| Aurora专属补丁训练 | Windows本地 | 原模型预测+真实标签+ENSO | 两类小模型 | 不用再次运行Aurora |
| 独立测试、画图、汇报 | Windows本地 | 固定模型与留出数据 | 误差、区间、案例 | 比较ENSO额外作用 |

### 0.1 主路线的模型选择

这一版固定 **Aurora 0.25° Pretrained + ERA5 + 官方Tracker**。
原因：官方建议ERA5使用Pretrained；Fine-Tuned版本对应HRES T0，不能随便换输入。
官方台风追踪建议使用Fine-Tuned，这意味着本路线是数据易获取的试验路线，不是官方最佳台风配置复现。
后续如实验室能获取HRES T0，可以新开版本适配；不要在同一实验中混用。

注意：Python包版本`microsoft-aurora==2.0.1`不是“Aurora模型2.0”，
本方案也不是Aurora 1.5。权重固定为`aurora-0.25-pretrained.ckpt`。
常规全球0.25°推理官方参考约40GB显存；因此申请单卡48GB或80GB。
32GB参考属于Aurora 1.5，不能直接套用。

### 下载失败时

浏览器手动打开官方链接，“另存为”到指定路径。显示文件扩展名，防止文件变成.csv.html或.data.txt。
`.part`表示下载中断，不是完整文件；先检查并手动归档该具体残片再重试。
网页内容、登录页、代理错误页都不能当作数据。如果两种方式都无法下载，停在这里查网络，不伪造数据。

## 5. 【本地】先完成弱轨迹基线闭环

这一步用于练习和验证；后续真正目标模型是Aurora。

```bat
python scripts\pipeline.py prepare --run runs\local_baseline
python scripts\pipeline.py base --run runs\local_baseline
python scripts\pipeline.py train --run runs\local_baseline
python scripts\pipeline.py test --run runs\local_baseline
```

逐条执行，任何一步报错就在该步停下，不把后续报错堆叠。

| 命令 | 在做什么 | 为什么必要 | 成功输出 |
|---|---|---|---|
| prepare | 固定机构、时间、历史窗口、ENSO滞后，关联未来真值 | 把气象资料变成机器学习样本 | samples.csv、sample_counts.csv、data_manifest.json |
| base | 只用早期资料训练岭回归轨迹预测器 | 产生可解释的冻结原模型 | base_models.joblib、forecasts.csv |
| train | 在后续年份学习原预测残差，验证集选参数 | 学会对错误进行校正 | patch_models.joblib、validation_search.csv |
| test | 对留出年份计算误差与ENSO增益 | 检查泛化和有无ENSO的差别 | test_metrics.csv、test_predictions.csv、paired_year_bootstrap.csv |

默认本地基线划分：1980—1999训练base；2000—2014训练patch；2015—2018验证；2019—2024测试。
它与后面的Aurora配置不同，不混用。
历史输入仅用当前位置、最近6/12/24小时位移和月份，不用未来真值、年份编号或SID作预测特征。
ENSO使用两个完整月滞后及再前两月，不用起报月尚未结束的整月平均。
同一台风保持在同一集合，跨集合边界样本排除，历史24小时不使用未来插值。
使用USA_LAT/USA_LON，缺失就丢弃，不偷偷用JMA替换。这里不按强度阈值筛选，不应称“仅台风级强度样本”。
每个时效只评有对应未来最佳路径的案例；长时效样本减少是正常的，需要报告样本数。

## 12. 【服务器】配置CDS并获取一个起报时刻的数据

### 12.1 由你配置认证

浏览器注册/登录CDS，接受ERA5单层和压力层数据许可。
按https://cds.climate.copernicus.eu/how-to-api官方页面配置本账号的CDS API。
在服务器运行程序就要让服务器能读取合法配置；本地配置不会自动出现在服务器。
如果把认证文件放在服务器个人目录，仅本人可读，不加入项目ZIP或git仓库。
不要在聊天或日志公开token。本脚本使用标准cdsapi.Client()。

### 12.2 只取一个起报所需的两个时间

```bash
python scripts/server.py data --plan transfer/pilot/plan.csv --limit 1
```

这个limit指计划中最早1个独立起报时刻，不是1个台风。
以t=2023-08-01 00UTC为例，需要t-6h=7月31日18UTC和t=8月1日00UTC。
脚本按两个具体时刻分别请求，正确处理跨天、跨月和跨年，避免组合成多余时间。
附加静态字段固定下载一份2000-01-01的ERA5静态文件并锁定指纹，后续保持一致。

| 数据 | 变量 | 作用 |
|---|---|---|
| 地面两个时刻 | 2米气温、10米u/v风、海平面气压 | 近地表初始状态 |
| 高空两个时刻 | 温度t、u/v风、比湿q、位势z | 三维大气初值 |
| 13个压力层 | 50、100、150、200、250、300、400、500、600、700、850、925、1000 hPa | 统一垂直结构 |
| 静态一份 | 陆海掩膜、土壤类型、地表位势 | 地表背景 |

全部为全球0.25°，不能只下载台风附近区域塞入本路线。
数据保存于data/era5/YYYYMMDDHH/surface.nc、upper.nc和各自manifest；静态为data/era5/static.nc。
脚本验证缓存指纹，断点残片不会当成成功文件。
CDS排队可能很久，到网页查看任务，不重复提交相同大请求。
当前脚本的真实CDS下载和NetCDF转换尚未实测，若API格式变化，以网页“Show API request”为准修正后新开版本。

## 13. 【服务器】单步推理验收：先解决“能不能跑”

### 13.1 专用GPU机器或已分配的交互计算节点

```bash
python scripts/server.py run --plan transfer/pilot/plan.csv --output server_runs/step1 --limit 1 --steps 1 --save-msl
```

默认模型冻结、eval、inference_mode；无反向传播，无优化器。
程序读两时刻ERA5，检查时间、网格、压力层、数值与气压单位，转成Aurora Batch，再运行6小时预测。
输出时刻目录下的done.json是完整完成标志；error.json表示失败，不能当完成。

检查：

- 控制台打印lead_h=6；没有CUDA OOM。
- done.json包含wall_seconds、peak_allocated_gib、peak_reserved_gib、权重/输入指纹。
- forecasts.csv有官方Tracker提取的路径；若无有效轨迹，检查tracker_errors.json。
- msl_006.npz是用于人工检查的海平面气压场，不是完整多层场。

模型推理成功和追踪成功是两个验收项。即使第一步追踪失败，天气模型可能已经跑完。
先处理具体失败原因，不用未来真实中心强行纠正轨迹。
如果峰值超过显存，不承诺调整batch能解决；已经batch=1。应使用更大显存机器或另设计优化版本。

### 13.2 Slurm集群

不要在登录节点运行上面的GPU命令。请管理员提供实际的交互申请命令，或修改脚本run_server.slurm。
需要设置的字段包括partition、account、单卡型号/显存约束；模板`--gres=gpu:1`本身不能保证大显存。
模板当前跑20步。首次测试把脚本里`--steps 20`改为`--steps 1`、输出改成server_runs/step1。

## 14. 【服务器】跑一个完整120小时，再跑小试计划


首次保存各步MSLP便于审查，后续大批量不用--save-msl以减少磁盘。
相同起报时刻的多个台风共用这次全球推理，只各自建立Tracker。
每一步预测移到CPU处理并释放临时引用，不把20步所有完整场存进GPU列表。

记录一个完整起报耗时与显存，按计划的独立起报数估计总成本。
要完成最多6个案例的试验，先下载它们全部初值，再限量运行：


run最多新增N个尚未完成起报（已完成会跳过）。想扩大下载范围，需要把data的N增加。
这里既然计划最多6个案例，limit6足够覆盖。

### 14.1 追踪质量检查

官方Tracker也可能退回外推。输出tracker_fallback标记该步是否使用失败后的回退，fallback_count是累计次数。
检查首步失败、双台风身份跳转、登陆附近、极端转向、经度跨界等情况。
不要静默删除回退点；主评价保留有效输出并报告失败/回退比例。
若修正追踪规则，只用开发期确定，然后冻结并用新版本重跑，不依据测试真值修复。
本路线使用Pretrained而非官方追踪推荐的Fine-Tuned，所以质量检查尤其必要。

## 18. 【本地】训练Aurora专属的两类补丁

新建run，不复用小试导入目录：

```bat

python scripts\pipeline.py external --run runs\aurora_fit --config configs\aurora_pilot.json --input transfer\return_full\forecasts.csv --model-id aurora025_pretrained_era5_officialtracker

```

这里不运行base命令。Aurora已经是冻结基础模型，external导入它的真实历史预测。
补丁标签=真实位移−Aurora预测位移，单位公里。服务器不参与此训练，也不用反复生成同一份预测。

六个比较对象：

| 方法 | 内容 | 研究作用 |
|---|---|---|
| base | Aurora原始路径 | 原模型对照 |
| mean | 每时效平均残差 | 最简单偏差校正对照 |
| ridge_noenso | 岭回归补丁，无ENSO | 线性后处理作用 |
| ridge_enso | 岭回归补丁，有ENSO | ENSO在线性补丁中的额外作用 |
| tree_noenso | 梯度提升树补丁，无ENSO | 非线性后处理作用 |
| tree_enso | 梯度提升树补丁，有ENSO | ENSO非线性条件作用 |

每个时效单独训练。Ridge搜索正则10/100/1000，树最大叶节点7/15；
验证集选择校正系数0/0.25/0.5/1。系数0表示验证集不支持修正，合理保留。
不是逐样本动态门控，也不是神经网络LoRA/FiLM；方法名称按实际代码写。
最终只有小型joblib文件，按模型ID区分；不把旧弱基线补丁挂到Aurora后只改名字。

## 19. 【本地】最终测试与结果解读

冻结配置和选择规则后执行：

```bat
python scripts\pipeline.py test --run runs\aurora_fit --config configs\aurora_pilot.json
```

测试输出全部位于runs\aurora_fit：

- test_metrics.csv：每时效总体/ENSO分箱的mean_km、median_km、p90_km、样本数。
- test_predictions.csv：每案例每方法预测，便于核查。
- paired_year_bootstrap.csv：同案例配对的改善及按年份重抽样区间。

在Excel查看时只打开结果副本，不另存覆盖原始返回文件。
比较候选相对reference的gain_km，正数=改善，负数=恶化。
ENSO核心比较是ridge_noenso→ridge_enso和tree_noenso→tree_enso，不能只比较base。
误差用球面大圆距离；不直接计算纬度差加经度差。
月指数warm/cold/neutral分箱不是官方ENSO事件定义。按±0.5分箱不能直接称ONI事件。
测试仅3年，年度区间非常有限；基础权重历史未核清也限制解释。详见科研边界文档。
未实现登陆点、转向点、沿/横路径误差或概率评分，不宣称这些已经测试。
